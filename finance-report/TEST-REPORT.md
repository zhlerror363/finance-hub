## 1. 口径观察（任务书 §4 硬要求：实测分布，不许猜）

对 `demo.db`（**只读**）打印分布：

```
tx type:        expense 899 笔（301..76876 分）/ income 17 笔（37520..800000 分）
tx date:        '2025-10-01' … '2026-09-30'（YYYY-MM-DD 纯文本）
cat kind:       expense 28 / income 2
cat grp:        ''(2, 收入类) / '非必要'(28)
tx grp:         ('', income, 5) ('必要', expense, 757) ('必要', income, 12) ('非必要', expense, 142)
share_kind:     916/916 全空（源码注释：e.g. "÷2"，自由文本分摊备注）
amount ≤ 0:     0 笔
```

源码佐证（server/index.js）：
- L49 建表：`type TEXT NOT NULL DEFAULT 'expense'`、`grp TEXT DEFAULT '非必要'`
- L461：`(t.type === 'income' ? 1 : -1) * t.amount_cents` → **金额恒正，符号由 type 推导**
- L589-591 官方必要/非必要查询：`type='expense' AND t.grp IN ('必要','非必要')`（收入行的 grp 是噪声，demo 里工资行 grp='必要' 即证）
- L152：`share_kind ... -- e.g. "÷2"`

**本工具口径**（详见 README 表格）：必要/非必要仅支出行且 grp ∈ {必要,非必要}，与官方查询逐字一致；`share_kind` 未纳入统计（附录注明）。

## 3. 数字对账（任务书 §7.3：SQL + 手算 ≥4 项）

对 `tests/sample.db` 用独立 SQL 复算 vs 报告实际值：

| # | 项目 | 独立 SQL / 手算 | 报告实际 | 结果 |
|---|---|---|---|---|
| 1 | 总收入（user1, 2026-08） | `SELECT SUM(amount_cents) … type='income'` = **800000**（8000.00 元） | 8000.00 | ✅ |
| 2 | 总支出（含退款冲减） | 2500+3000+0+15900+2500+1800+30000**−5000**+6800+4500 = **62000**（620.00 元） | 620.00 | ✅ |
| 3 | 结余 | 800000−62000 = **738000**（7380.00 元） | 7380.00 | ✅ |
| 4 | Top1 | `ORDER BY amount_cents DESC LIMIT 1` = **30000**（2026-08-20 占位键盘） | 300.00 / 占位键盘 | ✅ |
| 5 | 分类「数码」 | 30000 + (−5000) = **25000**（250.00，退款冲减生效） | 250.00 / 2 笔 | ✅ |
| 6 | 必要 / 非必要 | 官方口径 SQL：必要 **25900**（259.00）、非必要 **36100**（361.00） | 259.00(41.7%) / 361.00(58.2%) | ✅ |
| 7 | 日均 | 支出 62000 ÷ 10 个记账日 = **6200**（62.00） | 62.00（按 10 个记账日） | ✅ |
| 8 | 环比支出 | (62000−5500)×1000÷5500 = 10272 → **+1027.2%** | +1027.2% | ✅ |
| 9 | 环比结余 | (738000−794500)×1000÷794500 = 71 → **−7.1%** | -7.1% | ✅ |
| 10 | 环比收入 | 两月均 800000 → **0.0%** | 0.0% | ✅ |

> 注：手算脚本里 `-56500000//794500 = -72`（地板除）曾显示 -7.2%，是验证脚本的假象；
> 工具内部用 `abs()*1000//abs()` 再补符号 = **-7.1%**，与真值 -7.113% 截断一致。
